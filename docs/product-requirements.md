# FinanceHub 产品需求说明书

## 1. 产品概述

FinanceHub 是面向财务部门、业务运营人员、系统管理员和集成运维人员的财务中台产品。系统通过统一工作台管理财务业务数据、凭证规则、凭证生成、对账、报表和外部系统同步，降低人工核算和跨系统对账成本。

## 2. 产品目标

- 建立统一的财务数据入口和查询入口。
- 支持租赁、资产转让、减值计提、服务费、保证金、税费等业务核算。
- 支持可配置的凭证生成规则，降低硬编码变更成本。
- 支持金蝶 EAS 凭证推送和结果同步。
- 支持多业务系统数据同步和异常处理。
- 支持角色、权限、字典、用户管理等后台能力。

## 3. 用户角色

| 角色 | 诉求 |
| --- | --- |
| 财务核算人员 | 查询合同、回款、费用、凭证，执行核算和凭证生成 |
| 财务主管 | 审核结果、查看报表、处理异常、确认账期和凭证状态 |
| 业务运营人员 | 查看业务单据状态、补充数据、处理审批和异常 |
| 系统管理员 | 管理用户、角色、权限、字典、组织 |
| 集成运维人员 | 管理外部接口、同步任务、异常消息、MQ/ETL 状态 |

## 4. 产品范围

### 4.1 包含范围

- 用户登录和权限控制。
- 系统管理：用户、角色、数据权限、字典。
- 引擎配置：业务场景、字段映射、规则、科目、税率、凭证模板。
- 财务业务处理：合同、租赁、回款、核销、费用、保证金、服务费、税费。
- 资产转让：普通转让、折价转让、第三方转让、ABS 出表。
- 计量业务：收益计提、减值计提、咨询服务费。
- 凭证业务：凭证生成、查询、自制凭证、凭证报表。
- 对账和报表：应收、保证金、保险费、金蝶科目、异常报表。
- 数据治理：异常消息、指标、主数据配置。
- 外部同步：金蝶、运营平台、微业、乘用车、商用车等业务系统。

### 4.2 不包含范围

- 金蝶 EAS 本身的功能实现。
- 外部业务系统原始数据采集端改造。
- 企业级 BI 分析平台。
- 完整工作流引擎实现，当前更像审批状态对接和消息消费。

## 5. 核心功能需求

### 5.1 登录与门户

需求：

- 用户可通过登录页进入系统。
- 登录成功后获取 token。
- 系统根据用户权限展示菜单和数据范围。
- 首页展示待处理事项、快捷入口或业务概览。

验收标准：

- 正确账号可登录。
- 无 token 请求被拦截。
- 用户信息接口返回当前用户。
- 前端 `/api` 请求经过本地或生产 gateway。

### 5.2 系统管理

需求：

- 管理用户、角色、角色用户授权、角色数据权限。
- 管理字典类型和字典数据。
- 查询操作日志。

验收标准：

- 管理员可以创建、修改、禁用用户。
- 角色和用户可绑定。
- 字典项变更后业务页面可读取最新字典。
- 操作日志可按条件查询。

### 5.3 引擎配置

需求：

- 配置业务场景。
- 配置场景字段、字段映射、业务规则。
- 配置科目、税率、凭证模板。
- 支持规则测试或凭证预览。

验收标准：

- 新增场景后可绑定字段和规则。
- 规则变更后生成凭证结果随之变化。
- 无效规则应给出明确错误。

### 5.4 合同与租赁业务

需求：

- 支持合同查询、合同详情、合同余额。
- 支持线下合同录入和还款计划维护。
- 支持租金确认、长期应收、长期收益、非确认收入、保证金等处理。
- 支持核销、诉讼费、应付保险、增值税、尾差调整。

验收标准：

- 合同列表可按客户、合同号、期间等条件查询。
- 合同详情展示基础信息、还款计划、业务结构和财务处理结果。
- 财务处理后可产生对应状态和凭证数据。

### 5.5 资产转让业务

需求：

- 支持普通转让、折价转让、内部转让、第三方转让。
- 支持 ABS 出表、赎回、付款、合同余额查询。
- 支持转让类业务凭证生成和报表查询。

验收标准：

- 转让业务单据可查询、查看详情、计算余额。
- 转让结果可进入凭证或报表链路。

### 5.6 计量业务

需求：

- 支持收益计提。
- 支持减值计提。
- 支持咨询服务费计划和明细。

验收标准：

- 计提任务可查询。
- 计提结果可回溯到合同或业务数据。
- 计提异常可被记录并处理。

### 5.7 凭证业务

需求：

- 根据业务场景和规则生成凭证。
- 支持自制凭证新增、详情、查询。
- 支持凭证查询、汇总、报表。
- 支持凭证推送金蝶和结果回写。

验收标准：

- 凭证头和分录金额平衡。
- 科目、辅助核算、币种、期间符合配置。
- 推送失败时记录错误并可重试。

### 5.8 对账与报表

需求：

- 支持租赁应收、保证金、保险费、科目余额、金蝶中间表等对账。
- 支持发送金蝶异常报表。
- 支持租赁表、全生命周期明细、付款单、批扣等报表。

验收标准：

- 报表可按期间、组织、合同、客户等条件查询。
- 对账差异可定位来源数据。
- 异常报表可导出或进入处理流程。

### 5.9 数据治理和异常处理

需求：

- 记录 MQ 消费、外部接口、凭证推送等异常。
- 支持异常消息查询和重推。
- 支持指标和主数据配置。

验收标准：

- 异常有明确来源、时间、业务键和错误信息。
- 重推后状态变化可追踪。

### 5.10 外部系统集成

需求：

- 同步金蝶基础资料、凭证、期间、科目、辅助核算。
- 从多个业务系统获取还款计划、回款、合同、费用等数据。
- 通过 ETL 或 Feign API 提供给 engine。

验收标准：

- 同步任务可手动或定时触发。
- 同步结果可查询。
- 接口失败有日志和异常记录。

## 6. 非功能需求

### 6.1 可用性

- gateway、auth、admin、engine 应支持独立启动。
- 外部系统不可用时，应尽量不影响基础登录和查询。
- MQ 或 XXL-JOB 不可用时，应有明确降级或告警。

### 6.2 性能

- 常用列表查询应支持分页。
- 大批量数据导入和同步应异步处理。
- 报表查询应避免全表扫描，必要时使用汇总表。

### 6.3 安全

- 所有业务 API 默认需要 token。
- 角色和数据权限控制应在后端生效。
- 外部接口凭据不应硬编码到源码。

### 6.4 可维护性

- Nacos 配置应按环境隔离。
- 后端 API 版本应和依赖分支保持一致。
- 私有 jar 应进入制品库。
- 启动脚本和本地配置应文档化。

## 7. 当前产品可用性评估

当前本地已验证：

- 登录链路可用。
- 前端可访问。
- admin 基础接口可用。
- engine HTTP 服务可启动并连接数据库。

当前不完整：

- ETL 未运行。
- RabbitMQ 未运行，engine MQ 消费不可用。
- XXL-JOB Admin 未运行，定时任务不可完整调度。
- 金蝶真实 LTPA token 依赖未补齐。
- engine/etl API 分支需要统一。

- 补齐 RabbitMQ。

P1：

- 补 XXL-JOB Admin。
- 验证凭证生成到金蝶推送的完整流程。

P2：

- 完善异常消息重试和可观测性。
