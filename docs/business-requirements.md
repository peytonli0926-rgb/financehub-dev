# FinanceHub 业务需求说明书

## 1. 业务背景

当前财务核算涉及多个业务系统、金蝶 EAS、合同和还款数据、银行流水、费用、资产转让、减值计提、税费、保证金和大量凭证规则。若依赖人工导出、手工整理和线下对账，会带来以下问题：

- 数据来源分散，口径不一致。
- 凭证生成依赖人工判断，效率低且容易出错。
- 金蝶和业务系统之间状态回写复杂。
- 对账差异定位困难。
- 定时同步和异常重试缺少统一平台。

FinanceHub 需要作为财务中台，把数据同步、规则配置、凭证生成、对账报表和异常处理整合到一个系统中。

## 2. 业务目标

- 建立统一财务处理平台。
- 支持业务数据到财务凭证的自动化转换。
- 提高凭证生成、对账和报表效率。
- 降低系统间人工搬运和重复录入。
- 保证财务处理过程可追溯、可审计、可重试。

## 3. 业务范围

### 3.1 合同和租赁业务

范围：

- 合同查询和详情。
- 线下合同录入。
- 还款计划维护。
- 租金确认。
- 长期应收和长期收益。
- 未确认融资收益。
- 保证金。
- 应付保险。
- 增值税。
- 核销和诉讼费。
- 尾差调整。

核心业务对象：

- 合同。
- 客户。
- 还款计划。
- 回款记录。
- 费用明细。
- 财务处理单据。
- 凭证。

### 3.2 资产转让业务

范围：

- 普通资产转让。
- 折价转让。
- 内部调拨。
- 第三方转让。
- ABS 出表。
- 赎回和付款。
- 转让合同余额。

业务目标：

- 支持转让业务的财务确认。
- 支持转让相关凭证和报表。
- 支持转让前后余额查询和核对。

### 3.3 凭证和会计引擎

范围：

- 会计场景配置。
- 业务字段配置。
- 字段映射。
- 科目配置。
- 税率配置。
- 凭证模板。
- 凭证生成。
- 凭证查询。
- 自制凭证。
- 凭证推送金蝶。

业务目标：

- 通过配置替代大量硬编码凭证规则。
- 同一业务类型可按组织、场景、期间或规则生成不同凭证。
- 支持异常可追溯和可重试。

### 3.4 计量和计提业务

范围：

- 收益计提。
- 减值计提。
- 咨询服务费。
- 计提计划和明细。

业务目标：

- 按账期生成计提结果。
- 计提结果可和合同、还款计划、凭证关联。
- 支持报表和差异分析。

### 3.5 对账和报表

范围：

- 租赁应收对账。
- 保证金对账。
- 保险费对账。
- 金蝶科目对账。
- 金蝶中间表对账。
- 异常报表。
- 租赁表、全生命周期明细、付款单、批扣明细等报表。

业务目标：

- 形成统一报表查询入口。
- 对账差异可定位到业务来源。
- 异常可进入处理和重推流程。

### 3.6 数据同步和外部系统

范围：

- 金蝶 EAS 基础资料同步。
- 金蝶凭证推送和状态同步。
- 运营平台、微业、乘用车、商用车等业务系统数据同步。
- 银行流水和付款数据同步。
- 定时任务和手工触发同步。

业务目标：

- 保证业务数据及时进入财务处理。
- 保证金蝶结果及时回写。
- 同步失败可追踪和重试。

## 4. 业务流程

### 4.1 数据进入流程

1. 外部业务系统产生合同、还款计划、回款、费用、银行流水等数据。
2. ETL 通过接口、定时任务或手动触发同步数据。
3. 数据落入 FinanceHub 业务表或通过 API 提供给 engine。
4. engine 根据业务类型进入对应处理流程。
5. 异常数据记录到异常消息或数据治理模块。

### 4.2 凭证生成流程

1. 财务人员配置业务场景、字段、科目、税率和规则。
2. 用户选择业务数据或系统按任务批量获取业务数据。
3. engine 执行规则匹配。
4. 生成凭证头和凭证分录。
5. 用户查询或审核凭证。
6. 系统推送到金蝶。
7. 金蝶返回结果，系统回写凭证状态。

### 4.3 对账流程

1. 系统同步业务系统数据和金蝶数据。
2. 按合同、客户、组织、科目、期间等维度匹配。
3. 输出一致项、差异项和异常项。
4. 用户查看差异原因。
5. 差异处理后重新同步或重新对账。

### 4.4 异常处理流程

1. 接口调用、MQ 消费、凭证推送或数据转换失败。
2. 系统记录异常消息。
3. 用户在数据治理或异常消息页面查询。
4. 用户修正配置或数据。
5. 触发重试。
6. 系统更新处理结果。

## 5. 业务规则

### 5.1 权限规则

- 未登录用户不能访问业务接口。
- 用户只能看到授权菜单。
- 数据范围应按角色、组织或用户授权控制。
- 管理员可维护用户、角色、字典和权限。

### 5.2 凭证规则

- 凭证必须有关联业务场景。
- 凭证分录应借贷平衡。
- 科目、辅助核算、币种、期间必须符合规则配置。
- 凭证推送失败必须保留错误原因。
- 已推送成功的凭证不应重复推送，除非有明确冲销或重推机制。

### 5.3 账期规则

- 业务处理应归属到明确账期。
- 金蝶账期和本系统账期应可同步和比对。
- 已关闭账期不应随意修改业务结果。

### 5.4 数据同步规则

- 同步任务应记录开始时间、结束时间、状态和错误原因。
- 同步数据应具备业务唯一键或幂等键。
- 重复同步不应生成重复业务数据。

### 5.5 MQ 规则

- 消费失败应记录消息内容、队列、错误和时间。
- 可重试消息应支持人工或自动重推。
- 不可重试消息应进入异常处理流程。

## 6. 业务数据需求

核心数据实体：

- 用户、角色、组织、字典。
- 合同、客户、合同余额、还款计划。
- 回款、银行流水、付款数据。
- 租赁收入、长期应收、长期收益。
- 服务费、保证金、保险费、增值税、尾差。
- 资产转让、ABS、赎回、付款。
- 凭证头、凭证分录、凭证状态。
- 科目、辅助核算、币种、会计期间。
- 对账结果、异常消息、同步任务。

数据质量要求：

- 业务主键稳定。
- 金额字段精度可靠。
- 期间字段格式一致。
- 外部系统数据保留来源标识。
- 异常数据可追踪到原始输入。

## 7. 集成需求

### 7.1 金蝶 EAS

需求：

- 登录获取 session。
- 查询基础资料。
- 同步会计期间、科目、辅助核算、币种等。
- 推送凭证。
- 查询凭证处理结果。

风险：

- 本地当前使用 LTPA stub，不能验证真实金蝶 token。
- EAS 地址和凭据应由 Nacos 配置管理。

### 7.2 外部业务系统

需求：

- 拉取合同、还款计划、回款、银行流水、费用、运营平台数据等。
- 对接不同业务系统的数据结构。
- 提供统一 DTO 给 engine 消费。

风险：

- ETL API 与 engine 分支不一致会导致构建或运行失败。

### 7.3 RabbitMQ

需求：

- 支持业务消息异步处理。
- 支持审批状态、业务数据、错误消息等队列。

风险：

- 当前本地 RabbitMQ 未运行，engine 虽然启动但 MQ 消费不可用。

## 8. 验收标准

### 8.1 基础链路

- Nacos、MySQL、Redis 启动成功。
- auth/admin/gateway/web 可用。
- 登录成功并可获取用户信息。
- 前端请求通过 gateway 进入后端。

### 8.2 Engine 链路

- engine 可构建。
- engine 可启动并注册 Nacos。
- engine 可连接数据库。
- gateway 可路由到 engine。
- RabbitMQ 启动后 MQ listener 不再持续报连接错误。

### 8.3 ETL 链路

- etl 可构建。
- etl 可启动并注册 Nacos。
- 定时任务 executor 可启动。
- 至少一个外部数据同步任务可跑通。

### 8.4 凭证链路

- 可配置凭证场景。
- 可生成凭证。
- 可查询凭证。
- 可推送金蝶并回写状态。
