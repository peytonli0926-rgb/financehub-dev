# 零售回租付款业务事件测试用例

## 测试前提

- 接口：`POST /retail-leaseback/payment/execute`
- 生命周期主合同：`HXZL-PC-202609-0001`。
- 起租单据：`HTQZ-20260903-0001`，客户“张华”。
- 后续8个付款事件全部沿用同一合同和客户，按“投放起租—初始费用—正常存续—提前结清”组成完整生命周期，不再为每个事件创建独立合同。
- 合同起租日为2026-09-03、原到期日为2027-09-03；测试设定在2027-06-20提前结清，体现真正的存续期和提前终止。
- 来源系统：`CYCXT`
- 所有来源事件通过 `eg_field_mapping` 映射到 `CYC_PAYMENT`。
- 所有事件共用“零售回租统一付款模板”。
- 正向用例必须满足：接口返回成功、`sceneCode=CYC_PAYMENT`、`validFlag=1`、实际分录完整包含预期分录，并且能在“我的单据 > 接口单据”查询及打开对应凭证。
- 测试银行账号已模拟完成金蝶同步：工商银行 `1002.01`、招商银行 `1002.12`、兴业银行 `1004.01`、浦发银行 `1004.06`。

## 异常用例

| 用例 | 场景 | 预期结果 |
|---|---|---|
| N01 | 使用未同步银行账号 | 拒绝处理，提示银行账号未同步或已停用 |
| N02 | 价税合计与付款总额不一致 | 拒绝处理，提示价税关系不成立 |
| N03 | 来源事件没有付款值映射 | 拒绝处理，提示事件未配置付款值映射 |
| N04 | 购入资产使用非法支付方式 | 拒绝处理，仅允许银行转账或银行承兑汇票 |

## 资产管理费付款模板修正验证（2026-09-07）

- 验证报文：`paymentAmount=1060.00`，未传 `untaxedAmount`。
- 计算结果：根据业务类型配置的 6% 税率，反算 `managementFeeAmount=1000.00`、`taxAmount=60.00`。
- 凭证结果：借 `220211` 1000.00；借 `222118` 60.00；贷银行明细科目 `1002.12` 1060.00。
- 接口不接收税率、税额，也不再要求 CR025 传 `untaxedAmount`。
- 验证通过后已清理临时单据，未在合同生命周期中保留重复付款事件。
